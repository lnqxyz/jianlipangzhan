# jianlipangzhan · 监理旁站记录表生成

## 定位

输入施工台账（Excel，最多三份），找到其中**最新日期**的记录，按 12 类旁站记录表分派规则
生成已填好的 Word 旁站记录表。数据全部来自台账；台账没有的字段填「/」并留痕（编号、签字栏、
落款日期留空不代填）；台账来的数据一律红色字体。

## 何时使用

- 用户给了台账文件（.xls/.xlsx）要出旁站记录表
- 用户说「按台账生成旁站记录」「出今天/最新一天的旁站表」
- 用户点名某几类旁站记录表（表可指定，见「指定表」）

## 不适用

- 手工填写空白旁站表（没有台账时）
- 监理日志、监理通知单等其他监理文档
- 修改已生成的旁站表（重新生成为主）

## 工作流程

### 第 1 步 认台账（分派）

按**文件名**关键词分派（口径与 `scripts/extract_latest.py` 的 `detect_type` / 取数函数一致）：

| 文件名含 | 生成表（序号） | 张数 |
| --- | --- | --- |
| 监理台账（或 施工台账） | 1 隧道开挖、**3 超前小导管注浆**、**6 二衬带模注浆**、7 喷射混凝土、9 防排水安装、10 超前水平钻孔/加深炮孔、11 二衬预埋槽道、12 综合接地 | 8 |
| 旁站注浆记录表（或 旁站灌注记录表 / 注浆记录表台账） | 2 砂浆锚杆注浆、4 中空锚杆注浆、5 锁脚锚管注浆 | 3 |
| 配料单及拌合物（或 拌和物 / 配料单台账） | 8 混凝土浇筑（**起止时间另从监理台账对应浇筑时间列补**；只给配料单时这两格填「/」） | 1 |

- 3 号、6 号名字带「注浆」，数据却在**监理台账**（3 ← 超前小导管 sheet；6 ← 暗洞二衬的注浆时间列 + 带模注浆浆量列）。只给注浆台账时这两张出空表并进 `missing`。
- 反过来，注浆台账只出 2/4/5 三类；1/3/6/7/9/10/11/12 一律从监理台账取，别指望注浆台账里找。 
- 8 号的部位/配合比/材料来自配料单，旁站起止时间只能靠监理台账补；两份都传才是完整表。

文件名认不出 → **先问用户**，不要猜。

### 第 2 步 提取最新日期数据

**命令约定**：本节所有命令都在**技能目录**（本 `SKILL.md` 所在目录）下执行，脚本与模板路径一律
写相对路径（`scripts/…`、`assets/…`）。先 `cd` 到技能目录再跑，不要再自己拼技能目录的绝对前缀。

**三份台账一次传**（缺哪份就少传哪份，但 12 类要出全就三份都传；换文件只动 `L1`～`L3` 三个变量）：

```bash
mkdir -p out
L1="/Users/lnq/Documents/数字化监理/台账/淘金山隧道施工台账2026.11.9.xls"
L2="/Users/lnq/Documents/数字化监理/台账/注浆记录表台账.xlsx"
L3="/Users/lnq/Documents/数字化监理/台账/配料单及拌和物台账.xlsx"
python3 scripts/extract_latest.py "$L1" "$L2" "$L3" --pretty > out/extract.json
python3 -m json.tool out/extract.json | head -30   # 先看一眼结构
```

- 输出 JSON：`ledger_date`、`tables[]` **恒为 12 项**（每张表有 fields/records，台账
  数据已包 ⟦…⟧ 标红记号）、`missing[]`、`warnings[]`。
- 退出码：0=有数据；1=读到了但全无数据；2=文件读不了；3=类型认不出。
- 每张表带 `source[]` 溯源：`{sheet, row, cells}` = 这条内容取自哪个台账的哪个
  sheet、Excel 第几行、哪几列。交付时把 source 汇成一张「数据溯源清单」给用户，
  让他能一格一格回查台账（用户明确要求过「核对一下」）。
- **每张表各自取「本类有工序时间的最近一条」**，所以 12 张表的日期不一定相同（这是
  对的：某天没有这类作业就往前找，直到找到有旁站起止时间的那天）。
- 12 类的取数口径（已实现，改脚本时别退回去）：

| 序号 | 取数来源（sheet + 列） |
| --- | --- |
| 1 隧道开挖 | 各台阶开挖 sheet，按开挖时间链**开始日**分组，取最近一组 |
| 2 砂浆锚杆注浆 | 注浆台账标题「锚杆注浆记录表」且配合比含「砂」的 sheet |
| 3 超前小导管注浆 | **监理台账「超前小导管」sheet**（注浆时间 / 施做日期 / 根数） |
| 4 中空锚杆注浆 | 注浆台账标题含「中空」的 sheet |
| 5 锁脚锚管注浆 | 注浆台账标题含「锁脚」的 sheet |
| 6 二衬带模注浆 | **监理台账「暗洞二衬」**：注浆时间列 + 带模注浆浆量列 |
| 7 喷射混凝土 | 台阶开挖 / 仰拱初支 / 通信洞室初支 的喷锚时间，按开始日分组 |
| 8 混凝土浇筑 | 配料单「开盘信息汇总」，取**结构混凝土**最近一条；起止时间从监理台账对应浇筑时间列补 |
| 9 防排水安装 | 暗洞二衬 / 仰拱 的「土工布、防水板铺设」「盲管安装/防排水板」列；**旁站起止取主工序（土工布/防水板铺设）自己的时间**，盲管安装只作记录项列出，不与主工序拉成一次跨 8 天的旁站 |
| 10 超前水平钻孔、加深炮孔 | 超前水平钻时间列 + 加深炮孔**按日期分组合并同组多孔** |
| 11 二衬预埋槽道 | 接触网槽道 sheet：施工日期 + 时间列 |
| 12 综合接地 | 暗洞二衬 / 仰拱 的「钢筋、接地安装」+「接地电阻」列 |

- 3/6/9/12 已能从监理台账取到真实数据，**不再按「台账无表页」出空表**；某类实在无
  记录时 `missing[]` 会给出原因，照常出表、字段填「/」并留痕。

#### 项目名称（隧道名）在台账里的位置（已实测，直接照抄，别再猜）

用户口径：「旁站的项目名称直接取自台账标题」，且项目名属于台账来源数据、**要标红**。
三份台账里隧道名分别在这几处：

| 台账 | 位置 | 实测原值 | 取值规则 |
| --- | --- | --- | --- |
| 监理台账（.xls） | **每个 sheet 第 1 行 A1**（置顶标题框），如「淘金山隧道进口上台阶开挖台帐」 | 淘金山隧道进口… | 取「进口/出口/斜井」之前的部分 |
| 旁站注浆记录表台账 | 第 4 行「工程名称」标签右侧一格（c3 是标签，值在其右侧相邻非空格） | ` 淘金山隧道进口` | 去首尾空格、去「进口」 |
| 配料单及拌和物台账 | 「开盘信息汇总」**c4「单位工程」**（表头在第 6 行） | 淘金山隧道 | 直接用；**不要用 c10「工程名称」**——那列全项目都写「隧道工程」，取不到隧道名 |

实现位置：`proj_of()`（监理台账）、`meta['proj']`（注浆台账）、表 8 的 `_pj8`（配料单 c4）。
三处统一成「淘金山隧道」这一形态，再包 ⟦…⟧ 标红。

#### 旁站内容 / 旁站过程记录：整段全红

- 旁站内容（第 2–4 行右侧）是**一个纵向合并的单元格**，不拆成三行三格；内容全部来自台账，
  **整段合成一个红 run**，连「：」也红，`⟦…⟧` 记号在这一格失效；
- 旁站过程记录格：每条台账记录**整段红**，含「1、」编号、「工法 / 围岩 / 循环进尺」这类标签、
  单位与「；」，以及「（合计 … L，推算）」里的推算值；
- 固定格头「旁站过程记录：」、末尾三条检查项和「/」仍留黑（固定格式，不是台账数据）；
- 其余格保持「值红、标签黑」。

### 第 3 步 生成 Word（模板填写 → 后处理；模板丢了才用 Univer 重建）

版式已定型（对齐表 A.0.2 样板，用户多轮验收过的 12 行版）：

1. 表外：标题（居中加粗，**无表号**）+ 信息行「工程项目名称：…　施工合同段：…　编号：」
2. 表内 12 行：日期/天气/环境温度 → 旁站项目名称/旁站内容（右侧旁站内容为**跨三行合并的一格**）→ 开始/结束时间
   → 旁站过程记录（**一格多段**：模块名单独行 + 条目逐段）→ 其他说明 → 发现问题
   → 间隔行 → 签字三行（内部无横线）
3. 末尾三条固定检查项默认勾「是」（人员到位 / 机械压力表 / 原材料检验），编号紧接前面的过程记录连续顺延——2 条记录后是 3、4、5，5 条后是 6、7、8；
   不达标的情形走「发现问题及处理意见」，不改勾选
4. 天气、环境温度等台账没有的字段填「/」；**编号留空手填**——不填「/」，也不进
   「以 / 代填」清单（编号不是「无此项」，是待人工填写的表头项）

**模板长什么样**：20 源行 × 6 列（列宽 [98,132,84,104,100,52]）。20 源行 =
日期行 1 + 旁站项目/内容 3 + 起止时间 1 + 过程记录 9（模块名 + 8 条）+
其他 1 + 发现 1 + 间隔 1 + 签字 3。现成模板在
`assets/template-20rows.docx`（相对技能目录，`<w:tr` 计数 20），**优先直接用它**。

**A. 常规路（推荐，全程命令行，不需要 Univer 建表）**

```bash
python3 scripts/fill_docs.py out/extract.json assets/template-20rows.docx out --no 1
# 产出 out/raw-1.docx；把 records[]（含 ⟦⟧ 记号）填进旁站内容行与过程记录各条（这两格由 postprocess 整段转红）
python3 scripts/postprocess.py out/raw-1.docx out/pp-1.docx --records 1
python3 scripts/fix_merge.py out/pp-1.docx out/fin-1.docx
```

- `--records` 填该表 `len(tables[N-1].records)`，决定「旁站过程记录」格的行高
  （空表不留大片空白）。例：表 1 实测 `records` 长度 1，就传 `--records 1`；
- postprocess 负责：A4 版面 / 合并修复 / 一格多段 / 三条检查项注入（默认勾「是」）/
  签字区去横线 / 两格整段红 + 其余格 ⟦⟧ 转红色 / 自检；
- fix_merge 负责：导出 docx 里合并行残留的空 `<w:tc>`（Word 里表现为多余竖线）；
- **不写 `--records` 会让行高按 12 条算，短表留下大片空白**。

**B. 模板丢了才走这条**：用 Univer 宿主跑 `assets/build_form.js` 重建 20 源行表
（内容按脚本注释替换），`univer_export` 出 docx 当模板，再回到 A 路。

**收尾（两条路都要）**：`selfcheck=PASS` 后必须做**渲染核对**才算完成。本机没有通用的
Office 渲染命令（旧文档里若写别的渲染工具名，一律忽略），用 Univer 三件套：

1. `univer_worktree` 建一个临时草稿工作区，`univer_import` 把 `fin-N.docx` 导入该工作区里的
   临时 `.univer`（一张表一个 Doc Unit）；
2. `univer_status` 取该 Doc 的 `unitId`；
3. `univer_screenshot` 出 PNG，逐张看：**单页**、旁站内容与过程记录两格整段红、其余格红色只落在台账值上、无多余横线竖线。

核对不过就回头改脚本重跑，这是验收纪律，不许跳过，也不许拿「本机没渲染工具」当理由。

### 指定表

用户只要部分表时：从 `tables[]` 里挑出点名的序号生成，其余不出；`missing` 说明仍要
给（哪几张因无数据是空表）。

## 输出格式

- 文件名：`旁站记录表（类型名）YYYY-MM-DD.docx`，一个类型一个文件；
- 交付说明必须带：台账最新日期、每张表来自哪个 sheet、missing 清单（以 / 代填留痕）、
  红色 = 台账来源数据的说明（旁站内容 / 过程记录两格整段红）。

## 常见坑

- **.xls 别用 pandas 直接读**（缺 xlrd）；extract_latest.py 已内置 xlrd 直读，.xlsx 走 openpyxl。
- **注浆台账每个 sheet 是一张独立记录表**（r1 嵌表标题、r4 注浆日期、r5 列头、r6+ 数据）；
  标题字间有空格，匹配前先去空格；砂浆锚杆 = 标题「锚杆注浆记录表」且配合比含「砂」。
- **配料单「开盘信息汇总」表头在第 5 行**（含「序号」的行），r0–r3 是上一打印区残留，
  从表头行开始读。
- **日期列形态混存**：Excel 序列号、'2026.7.4' 字符串、datetime 三种都有，extract 已归一化；
  自己写解析时必须先归一化再比大小。
- **Univer 表格单元格只渲染第一段**——多行内容要么各占一行由 postprocess 合并成
  一格多段，要么写成单段连续文字；直接往单元格里塞 \n 会丢内容。
- **Univer 导出的合并行会残留空 `<w:tc>`**（同行第二处及以后的合并），postprocess/fix_merge
  负责修；不要手工改 XML 绕开它。

## 红线

- 台账是唯一数据源：台账没有的数据**一个字都不许编**（天气、环境温度填「/」；编号、签字栏、
  落款日期留空手填——它们都不进红色）。
- 编号、签字栏、落款日期永远留空，不代填；编号不属于「无此项」，**不填「/」、不进
  「以 / 代填」清单**（与第 3 步第 4 条同一口径）。
- 生成后必须渲染核对再交付；`selfcheck=FAIL` 的产物不许出。
- 台账来源数据全部标红；黑色只用于表头、固定格式与「/」。
- **两格整段红**：旁站内容、旁站过程记录整段红（含编号、标签、单位、推算合计），
  不再逐值包记号；固定格头、三条检查项、其他格的「/」保持黑。
- **红色不再区分原值与推算**：推算值同样整段红，但文案必须写「推算」二字
  （例：`注浆量 … L（合计 114.2 L，推算）`），靠文字而不是颜色区分。
